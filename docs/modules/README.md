# 模块开发日志

站点按模块维护开发日志，一个模块一份。记录当前状态、文件地图、已完成和下一步，目的是让下一次会话能直接接手。

- 总交接：`docs\site-log.md`
- 版本流水：`docs\version-log.md`
- 单模型交接：`docs\models\<slug>.md`

## 模块清单

| 模块 | 日志 | 入口 |
| --- | --- | --- |
| 文章 | `articles.md` | `/` |
| 分享 | `share.md` | `/share/` |
| 学习 | `learning.md` | `/learning/` |
| 物理模型 | `physical-models.md` | `/models/` |

## 日志模板

新建模块日志时复制这段：

```markdown
# <模块名> · 开发日志

## 一句话
这个模块是什么、给谁用。

## 当前状态
版本、入口、是否上线、数量。

## 文件地图
页面、组件、脚本、样式、数据分别在哪。

## 数据来源
手册、讲义、外部资料、自己整理的内容。

## 已完成
## 未完成 / 下一步
## 最近变更
日期 + 版本 + 改了什么。

## 接手提示
先读什么、怎么跑、哪里容易踩坑。
```

## 更新规则

- 每个版本改到哪个模块，就更新对应日志的“最近变更”；状态或待办有变化也同步。
- 新增物理模型：在 `docs\models\<slug>.md` 建单模型日志，并在 `physical-models.md` 加一行。
- 日志写事实：路径、版本、页码、命令。不写口号。
- 交接前更新：当前状态、未完成、下一步。
- 总日志只记跨模块的事；模块细节留在模块日志里，不重复。
