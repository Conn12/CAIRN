结论先说：够用。

## 一个学习日志只需要四件事

- 写：一个 Markdown 文件
- 索引：构建时扫一遍文章目录
- 发布：把生成的静态文件交给托管
- 订阅：以后补一个 RSS 文件，也不难

这四件事都不需要服务器在运行时参与。

## 不需要的东西

登录、评论、数据库，这些功能看起来让网站更"完整"，但对一个人的日志来说，维护成本远大于收益：

- 登录：没有多用户，登录只是给自己添一道门
- 评论：真要交流，文章末尾留个邮箱更直接
- 数据库：文章本来就在文件里，多一层存储就多一份备份负担

> 复杂度是借来的，迟早要还。

## 什么时候会不够

- 想在站内搜索：文章少的时候，浏览器 `Ctrl+F` 就够了
- 想做实时数据：那已经不是日志站，而是另一个项目
- 想按标签筛选：等文章真的多到需要筛选再说

## 一条构建命令

```bash
npm run build
```

产物是一堆 HTML、CSS 和图片，放到任何静态托管上都能跑，没有运行时、没有冷启动、没有要升级的数据库。

---

先这样。够用就先用，不够再说。
